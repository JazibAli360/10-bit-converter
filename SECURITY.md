# Security policy

## Supported version

Security fixes are considered on the latest published release and the current
`main` branch. This is currently the `0.1.x` release line.

## What to report

Please report vulnerabilities in the application source, packaged app, release
workflow, or project-owned documentation/assets. Third-party FFmpeg or system
library vulnerabilities may also need to be reported upstream; a project
report can still help identify affected releases.

## How to report safely

Do **not** publish exploit steps, private files, credentials, or proof-of-
concept code in a public issue.

1. Use GitHub's private **Report a vulnerability** flow in the repository's
   Security tab when it is available.
2. If private reporting is not available, open a short public issue titled
   `Security contact requested` with no sensitive details. The maintainer can
   arrange a private follow-up.

Include the affected version or commit, macOS version, concise reproduction
notes, potential impact, and any suggested mitigation. Reports are handled on
a best-effort basis; please allow reasonable time for a response before public
disclosure.
